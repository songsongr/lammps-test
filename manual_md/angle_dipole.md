## Description[](#description "Link to this heading"){.headerlink}

The *dipole* angle style is used to control the orientation of a dipolar atom within a molecule [[(Orsi)]{.std .std-ref}](#orsi){.reference .internal}. Specifically, the *dipole* angle style restrains the orientation of a point dipole [\\(\\mu_j\\)]{.math .notranslate .nohighlight} (embedded in atom [\\(j\\)]{.math .notranslate .nohighlight}) with respect to a reference (bond) vector [\\(\\vec{r}\_{ij} = \\vec{r}\_i - \\vec{r}\_j\\)]{.math .notranslate .nohighlight}, where [\\(i\\)]{.math .notranslate .nohighlight} is another atom of the same molecule (typically, [\\(i\\)]{.math .notranslate .nohighlight} and [\\(j\\)]{.math .notranslate .nohighlight} are also covalently bonded).

It is convenient to define an angle gamma between the 'free' vector [\\(\\vec{\\mu}\_j\\)]{.math .notranslate .nohighlight} and the reference (bond) vector [\\(\\vec{r}\_{ij}\\)]{.math .notranslate .nohighlight}:

::: {.math .notranslate .nohighlight}
\\\[\\cos\\gamma = \\frac{\\vec{\\mu}\_j\\cdot\\vec{r}\_{ij}}{\\mu_j\\,r\_{ij}}\\\]
:::

The *dipole* angle style uses the potential:

::: {.math .notranslate .nohighlight}
\\\[E = K (\\cos\\gamma - \\cos\\gamma_0)\^2\\\]
:::

where [\\(K\\)]{.math .notranslate .nohighlight} is a rigidity constant and gamma0 is an equilibrium (reference) angle.

The torque on the dipole can be obtained by differentiating the potential using the 'chain rule' as in appendix C.3 of [[(AllenTildesley)]{.std .std-ref}](#allen1){.reference .internal}:

::: {.math .notranslate .nohighlight}
\\\[\\vec{T}\_j = \\frac{2K(\\cos\\gamma - \\cos\\gamma_0)}{\\mu_j\\,r\_{ij}}\\, \\vec{r}\_{ij} \\times \\vec{\\mu}\_j\\\]
:::

Example: if [\\(\\gamma_0\\)]{.math .notranslate .nohighlight} is set to 0 degrees, the torque generated by the potential will tend to align the dipole along the reference direction defined by the (bond) vector [\\(\\vec{r}\_{ij}\\)]{.math .notranslate .nohighlight} (in other words, [\\(\\vec{\\mu}\_j\\)]{.math .notranslate .nohighlight} is restrained to point towards atom [\\(i\\)]{.math .notranslate .nohighlight}).

The dipolar torque [\\(\\vec{T}\_j\\)]{.math .notranslate .nohighlight} must be counterbalanced in order to conserve the local angular momentum. This is achieved via an additional force couple generating a torque equivalent to the opposite of [\\(\\vec{T}\_j\\)]{.math .notranslate .nohighlight}:

::: {.math .notranslate .nohighlight}
\\\[\\begin{split}-\\vec{T}\_j & = \\vec{r}\_{ij} \\times \\vec{F}\_i \\\\ \\vec{F}\_j & = -\\vec{F}\_i\\end{split}\\\]
:::

where [\\(\\vec{F}\_i\\)]{.math .notranslate .nohighlight} and [\\(\\vec{F}\_j\\)]{.math .notranslate .nohighlight} are applied on atoms [\\(i\\)]{.math .notranslate .nohighlight} and [\\(j\\)]{.math .notranslate .nohighlight}, respectively.

The following coefficients must be defined for each angle type via the [[angle_coeff]{.doc}]angle_coeff.md){.reference .internal} command as in the example above, or in the data file or restart files read by the [[read_data]{.doc}]read_data.md){.reference .internal} or [[read_restart]{.doc}]read_restart.md){.reference .internal} commands:

- [\\(K\\)]{.math .notranslate .nohighlight} (energy)

- [\\(\\gamma_0\\)]{.math .notranslate .nohighlight} (degrees)

------------------------------------------------------------------------

Styles with a *gpu*, *intel*, *kk*, *omp*, or *opt* suffix are functionally the same as the corresponding style without the suffix. They have been optimized to run faster, depending on your available hardware, as discussed on the [[Accelerator packages]{.doc}]Speed_packages.md){.reference .internal} page. The accelerated styles take the same arguments and should produce the same results, except for round-off and precision issues.

These accelerated styles are part of the GPU, INTEL, KOKKOS, OPENMP, and OPT packages, respectively. They are only enabled if LAMMPS was built with those packages. See the [[Build package]{.doc}]Build_package.md){.reference .internal} page for more info.

You can specify the accelerated styles explicitly in your input script by including their suffix, or you can use the [[-suffix command-line switch]{.doc}]Run_options.md){.reference .internal} when you invoke LAMMPS, or you can use the [[suffix]{.doc}]suffix.md){.reference .internal} command in your input script.

See the [[Accelerator packages]{.doc}]Speed_packages.md){.reference .internal} page for more instructions on how to use the accelerated styles effectively.

::::: {#restrictions .section}
## Restrictions[](#restrictions "Link to this heading"){.headerlink}

This angle style can only be used if LAMMPS was built with the DIPOLE package. See the [[Build package]{.doc}]Build_package.md){.reference .internal} doc page for more info.

::: {.admonition .note}
Note

In the "Angles" section of the data file, the atom ID [\\(j\\)]{.math .notranslate .nohighlight} defining the direction of the dipole vector to restrain must come before the atom ID of the reference atom [\\(i\\)]{.math .notranslate .nohighlight}. A third atom ID [\\(k\\)]{.math .notranslate .nohighlight} must also be provided to comply with the requirement of a valid angle definition. This atom ID [\\(k\\)]{.math .notranslate .nohighlight} should be chosen to be that of an atom bonded to atom [\\(i\\)]{.math .notranslate .nohighlight} to avoid errors with "lost angle atoms" when running in parallel. Since the LAMMPS code checks for valid angle definitions, cannot use the same atom ID of either [\\(i\\)]{.math .notranslate .nohighlight} or [\\(j\\)]{.math .notranslate .nohighlight} (this was allowed and recommended with older LAMMPS versions).
:::

The [[newton]{.doc}]newton.md){.reference .internal} command for intramolecular interactions must be "on" (which is the default except when using some accelerator packages).

::: {.admonition .note}
Note

This angle style should **NOT** be used with fix shake.
:::
